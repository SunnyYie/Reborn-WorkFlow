# 从歌词、简谱及音频识别结构

## 先核对资料

把原始文件路径、SHA-256、歌曲/编曲身份、来源、录音版本、调的证据和选择状态一并记录。同名同调不是同一编曲的证明。文件名“原调”、谱上的调和用户确认调分别记录，不根据文件名证明音频声学调。

歌词文档可能同时有段落清单与完整结构表，须读表格并按版面顺序读取所有表段，不能只读 `Document.paragraphs`。复用旧活动结构要标成参考/编排建议，不沿用旧人员、BPM、读经/祷告小节数当成本次确认。

## 三层结构

1. 乐段库：V1、V2、C1、C2、B、LL 等以及各自原文；不要把同旋律不同歌词的段合并。
2. 参考演唱路径：音频每一次乐段出现及真实重复顺序，包含器乐、弱起、间奏与尾奏。
3. 现场编排：用户/乐手最终选择的路径、分工、动态、循环及话语位置，可与参考录音不同。

三者的确认独立。歌词标出 Chorus 只证明乐段标签，不证明唱几次；没有写 Bridge 不证明录音没有 Bridge。

## 简谱识别

先看整页/全谱，读明确标题、拍号、调、乐段标签及其作用范围。允许识别谱上歌词，保留来源及与原字的逐处核对；不把现代简谱音符当歌词字符。歌词分行变化可用于排版，不擅自改词。

小节计数须结合拍号、时值、小节线、反复起终点、一二房子、D.C./D.S./Coda 等实际路径。记录弱起/不完整小节，不把跨页、跨行、延音线视为新乐段。反复和房子用于演唱展开，不能重复计算两次末尾或漏掉弱起。

伴奏前奏/间奏可能根本未印在声乐简谱上。谱面没写则为未知，不填“0 小节”。识别不清的音符/文字需局部复核，不用模型自信或自动 OCR 分数代替事实核验。

## 音频分析

先检查可解码、时长、声道及实际采用版本；音频不上传外部服务，除非用户另行授权。有成熟拍点/对齐工具时复用，报告实际工具与局限。

将明确歌词与人声时间对应，结合旋律、和声重复和器乐变化判乐段。自动拍点和结构分割只是候选，不凭单一响度、静音或相似度给出语义标签。不能将容器元数据读取称为完成音乐分析。

小节数依赖拍号、拍点、第一强拍和边界：处理半速/倍速、弱起、延长音、rubato、变拍与掌声/说话干扰。只有时间差和粗略 BPM 时不能将 `时长 * BPM / 每小节拍数` 四舍五入成“已核实小节数”。BPM 估计只作为分析信息，正式标题仍留空等乐手。

逐段记录时间范围和计数依据。无法可靠听辨/对齐、没有音频理解能力或版本冲突时，将相应时间、小节及重复顺序设为未知；可用已明确材料组装草稿并清楚交代，不声称已听完或已数清。

## LL 与 Tag

本团队约定：LL 一般是 Chorus 结尾的一句/两句，被单独抽出唱或重复；Tag 一般位于 LL 之后，是另一段独立收尾。多数只有 LL，没有 Tag。

《无人能与祢相比》为用户给定定义示例：LL 对应“我要敬拜祢 / 我要敬拜祢耶穌我的主”，其后的“噢”为 Tag。此例不意味着所有长音、衬词或所有结尾“噢”都叫 Tag。

已印/已唱的 LL 与其他歌词段分开。按用户最新规则，结束编排不自动从副歌末句抽取新 LL：没有明确独立 LL 就不加入。已有 Verse、Chorus、Bridge 等类型必须覆盖，不能用 LL 替代 Bridge。先查 RAG ending 记录；不足时生成明确标记为派生草案的完整覆盖编排，不改写原始历史表。

## 分析记录示意

每次出现一条记录：

```json
{
  "label": "IN",
  "occurrence": 1,
  "lyric_section": null,
  "audio_start": null,
  "audio_end": null,
  "bars": null,
  "evidence_type": "reference_arrangement",
  "source": "实际文件及表格/页码/时间范围",
  "status": "needs_confirmation",
  "note": "示例字段结构，非实际分析结果"
}
```

`evidence_type` 可区分 explicit_document、score_reading、audio_inference、reference_arrangement、user_decision。未知保持 null，不写 0 或制造时间戳；同一结构的不同字段允许不同来源。不伪造置信度百分比。

## 提交确认及回归检查

预览同时给乐段清单、展开顺序、可核实的小节数/时间、疑点和本次现场调整。分工、动态、话语循环不要从录音自动定案；前奏前话语不占前奏小节，间奏祷告必须与真实可用长度分开核对。

用户确认之后才标记现场版本已确认，且须指向具体修订；选择歌名不等于确认分析。后续换版本、修改反复或节拍时重新验证受影响的段。

至少检查：

- 标签已有但无结构表：不能称为顺序已知。
- 多个 MP3：不得静默任选，草稿须标明本次未选定版本。
- 累计顺序未对齐音频末尾：不能声称完整分析。
- C1/C2、房子与跨行弱起：不得漏段/重复计算。
- 没有 LL/Tag：允许没有，不强行补；现场提议抽末句须明确性质。
- 前奏未知：空/待确认，不从旧模板继承计数。
- 歌词识别有疑点：明确位置，不能润色消除冲突。
- 标题 BPM 没有乐手来源：保持空白。
