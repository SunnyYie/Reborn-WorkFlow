# 强制样式与分页验收

本规则适用于每次组装后的待审及正式歌单，是交付门禁，不是可选美化。以本次用户要求优先；不能用“模板保真”“测试通过”或“看过全部页面”代替逐项验收。

## 固定版式

- 前三首各自从新页开始，任何一页不得混放两首主歌。优先每首标题、经文、结构表和完整歌词都在同一页。
- 回应与结束合放在一个新的独立页，不与第三首或口述附录混排。新增回应需要完整歌词时也先尝试同页排版；放不下不能默默延续到别的歌曲页或省略歌词，须调整并重新验收，必要时向用户说明冲突。
- 口述附录另起页，不占用歌曲正文或回应/结束页；附录内部仍按发言位置组织。
- 歌词段落保持整行，乐段标题跟随正文，同一乐段的相邻歌词使用keepNext保持连续；不把两栏或整首强行串成无法分页的keepNext链。先消除无效空行、核对栏宽与段间距、压紧结构表，不靠删词、裁切、挤压行距或过小字体强凑一页。
- 过长歌曲确实跨页时，每个续页仍只能是该首；记录实际页码、原因和已尝试的排版调整，不能留下仅有标题/表格的孤页或隐瞒歌词续页。跨页例外不豁免其他样式检查。

## 逐首样式

| 对象 | 必须核对 |
| --- | --- |
| 主歌标题 | 微软雅黑16pt，加粗，深红C00000，与后续内容连续 |
| 回应/结束标题 | 微软雅黑14pt，加粗，深红C00000 |
| 经文 | 楷体_GB2312，12pt；原文、出处、折行可读 |
| 歌词及乐段标题 | 黑体14pt；标题加粗/下划线；左右首标题与首行歌词分别水平对齐 |
| 段落 | 普通段及两栏首标题段前0；同栏后续乐段标题段前240twip（12pt）；普通段后30twip，标题段后90twip；240自动行距；歌词不拆行 |
| 颜色 | V蓝2E75B6，C/PC橙C55A11，B/LL/Tag绿548235；标记、段标题、歌词正文一致 |
| 结构表 | 两行，表格/网格/单元格宽度一致，固定列布局；每列随内容600至1800twip，总宽不超过8300twip，长结构分连续表段 |
| 行高/间距 | 两行精确等高，按最长内容计算，最低440twip；文字行距264twip，段前后0，单元格垂直与水平居中；上下内边距60、左右120twip；不跨页拆行 |
| 表格字色/底色 | Arial/中文微软雅黑11pt，上排加粗；字色按对应乐段，底色V为9CC2E5、C/PC为F4B083、B/LL/Tag为A8D08D，器乐白底黑字 |
| 器乐标记 | 结构表和提示统一IN，保留原有位置与小节，不合并段落 |

### 左边界、留白与宽度协调

- 标题、经文、结构表外框和左栏歌词共用同一左边界；右栏歌词在自身栏内左对齐。正文显式左对齐、左右及首行缩进为0；表格左对齐，补偿120twip单元格左边距，防止外框伸出正文边界。经文的“【”视觉留白不通过额外空格修正。
- 结构表下方到歌词区保留明确呼吸空间：双栏之前统一增加180twip（9pt）精确高度留白；两侧首个乐段标题段前仍为0，防止WPS对栏首段前距的处理不同导致错行。仍须实际核对两侧基线，不能只在左栏加空行。
- 相邻乐段之间另设明确留白：同栏第二个及后续乐段标题段前240twip（12pt），适用于Verse 1/Verse 2、Chorus/Bridge及PC、LL、Tag等；段内歌词行距不变。不用空行堆叠，不把上一乐段尾句与下一标题组成keepNext链；标题仍跟随自身歌词。每首必须记录`section_spacing`，只有单乐段时说明不适用，不伪造多个乐段。
- 主歌结构表在内容宽度基础上以6000twip（约10.6cm）为适中最小总宽，增量分给各列、每列上限1800；列数太少时尊重上限，长表仍不得超过8300。不缩小较长内容列、不拉满整行；回应/结束短表仍按内容收紧。本次前两首均6000，避免第二首只有第一首约七成宽。
- 原生验收新增`left_edges`、`table_lyric_gap`、`table_width_balance`三项，并在观察中明确对齐、实际留白和三首宽度协调；回应/结束另检查`left_edges`。新文档必须取得这些观察，v3旧验收不能覆盖。

程序在导出前及artifact-finalize新验收（或低层artifact-review）时检查可判定的OOXML不变量。实际字体替代、视觉基线、分页、留白与美观仍必须在WPS或Word逐页查看；辅助渲染器缺字或页数不一致不能视为通过。通过后立即artifact-finalize合并收尾，只留当前最终稿及sources；关闭观察、哈希与引用门禁见workflow README，不等用户另行提醒。既有同哈希有效观察可复用，不补造新的目检记录。

## 验收记录

接口细节集中在workflow/README.md。新版导出带required_review_version=5，只有v5完整验收可用于交付完成、替代旧稿和清理。旧验收仍作历史证据，不能复制给新文件。

- `visual.pages[]`逐页填写观察和`blocks`：一首主歌用`["main:1"]`、`["main:2"]`或`["main:3"]`；回应/结束页只允许`["response","ending"]`且恰好一页；口述附录用`["spoken"]`。
- 三首的`songs[]`逐项检查字体、字号、颜色、段落与歌词间距、表格样式与尺寸、左右基线、IN和单曲分页。`pages`及`lyrics_pages`必须对应实际页码，不遗漏续页。
- `visual.response_ending`单独记录实际页码，以及回应/结束字体、字号、颜色、间距、表格样式/尺寸、IN和独立合页检查，不能只检查前三首。
- 跨页歌曲另填`pagination_exception:{"reason":"实际原因","adjustments":["实际尝试过的排版调整"]}`。没有实际尝试不得补造记录。
- 缺检查、混排、回应/结束不合页、歌词跨页未说明、结构样式失败时，修复后重新导出和验收；不能勾选忽略。WPS不可用、锁屏或无法确认页面时保持待验收，不登记通过，不清理唯一已验收版本。

验收后运行status确认visual_review_valid，再按已有安全清理流程收尾。此验收只证明文档检查，不代表乐队排练通过。
