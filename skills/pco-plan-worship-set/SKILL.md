# 按主题规划敬拜歌单

## 工作范围

把用户想表达的内容转化为有歌词依据的选歌和顺序建议。优先理解用户已经选好的歌，不默认全部替换，不将某次推荐固化为所有场景的最佳歌单。

本 skill 负责主题分析和方案比较；库内检索可按需读取相邻的 [搜索 skill](../search/pco-search-songs/SKILL.md)。不自动下载附件、不转录或 OCR，不修改 PCO 歌单、歌曲、编曲和排班。用户另行要求下载时再读取 [下载 skill](../download/pco-download-chinese-lyrics/SKILL.md)。

## 1. 提炼用户需求

- 区分总主题、叙事阶段、会众回应和音乐限制。例如“未认识神时迷茫 → 逐渐认识神而改变 → 坚定跟随”是三个不同的叙事职责，不只是三个相关关键词。
- 保留用户暂定的歌名、顺序及不可替换项。未说必须保留时，将它们当作偏好而非硬约束；未说已定稿时不要替用户宣布决定。
- 同时考虑已明确的慢速、柔和、语言、数量、聚会时长和环节。只追问会实质改变方案的缺失信息，不为可选细节阻塞分析。
- 不虚构用户的信主经历、情绪或见证。开场见证只能作为可选的表达方式，具体内容来自用户。

## 2. 取得歌词与编曲证据

- 先按 [历史歌单 RAG](../../rag/SKILL.md) 检索用户歌名，取回存量歌词、完整结构和来源；注明是历史编排。已选版本的完整资料可直接交给组装 skill，免下载与音频结构分析。没有命中的部分才补查 PCO；历史快慢/调性不冒充本次乐手确认，同名多版先比较，不静默覆盖。

- 优先读取用户提供的歌词、当前 PCO 编曲 `lyrics`、已授权取得的原始中文文档。历史来源注明时间，当前确认需重新查询。
- 中文译词可能与英文版本侧重点不同。仅查到英文歌词时，分析对应版本并标记中文版本待核对，不宣称已验证用户要唱的译词。
- 歌词字段空不代表没有歌词或主题不符；只能标注证据不足。不要仅按歌名给出强结论，不把旧的人工转录文本当成 PCO 原始来源。
- 只读命令可用：

  ```sh
  pco songs search --query "<歌名>" --include-arrangements --json
  pco songs arrangements <song-id> --json
  ```

- 使用现有认证，不在文档、回复或日志中保存凭据。网络、权限与缺失的处理按搜索 skill；不为获得证据擅自触发附件下载。
- BPM、拍号、调性、音域、时长有实值才记录；未知则标未知。未试听不声称已验证音色、柔和程度或实际演奏衔接。

## 3. 评估暂定歌单

对每首歌判断它“实际在说什么”，再看它承担的阶段是否合理：

- 叙述视角：尚在寻找、已经蒙恩、回顾经历，还是祈求与委身？
- 核心动作：寻求、呼求、认识、信靠、悔改、更新、感恩或跟随？
- 时间关系：回顾过去、表达现在、祈愿未来？“求神改变我”不等于“见证我已经改变”。
- 回应力度：寻求帮助、渴慕同在、愿意顺服、全然归属，不应混成同一个阶段。

用简短表格说明“歌曲 / 核心表达 / 匹配与缺口 / 更合适的位置”。主题概括优先，不大段复述歌词，不牵强解释歌曲来迎合原顺序。

然后评估整体：阶段是否缺失、反复、倒退或跳跃；最后是否落在用户要的回应，而不只是情绪高潮。歌曲次序不必机械模拟时间线，但偏离时应解释它表达的是哪一种推进。

## 4. 给出有取舍的方案

方案数量随问题需要，通常提供：

1. **最小改动方案**：保留原歌，只调整顺序；若仍有缺口，明确说明，不伪装为完全匹配。
2. **主题更贴合的方案**：只替换有明确收益的位置，解释新歌补了什么、放弃了原歌什么。

必要时才提供第三种不同方向，例如“更偏生命见证”与“更偏祷告回应”。不要列出许多近似歌单却不作判断。

- 每套明确歌序及各首的叙事职责，不只给歌名列表。
- 库内有依据的替代优先；库外推荐单独标为库外，不能冒充现有资源。
- 若没有歌能真实承担某阶段，可以建议用简短见证、经文或祷告连接。说明这是补充背景，不能声称歌曲歌词已覆盖缺口。
- 替代方案必须一并考虑用户原有音乐条件。主题更好但明显更快、中文歌词未确认或会众熟悉度未知时，说明代价。
- 最后给出一个优先推荐及适用理由；用户保留最终决定权，不自动写入 PCO。

## 5. 音乐与现场边界

- BPM 低不等于柔和；慢歌也可能有强烈桥段。配器、鼓组、演唱和动态建议要与已验证编曲事实分开。
- 不同拍号、拍点单位、半拍速度不能直接按数字比较。
- 调性、音域或版本未知时，不宣称能无缝串联、不擅自定调或降速。曲目时长只可作参考，不能当作含重复、祷告和过场的最终时长。
- “坚定跟随”不必须以快歌或大音量结束；根据歌词回应判断，而非只看音乐能量。
- 若提出串词，只表达主题过渡，不代替用户编造个人经历；若未要求详细串词，无需写长篇主持稿。

## 回复结构

先给明确结论：原方案是否成立、最关键缺口是什么。接着逐首分析，再给少量方案和最终推荐，最后简述未核对项。

分别标明：当前歌词依据、历史附件依据、音乐编排建议、未知信息。推荐不是定稿；不要将用户本次暂定歌单记成永久偏好。

## 决策验收

- 已蒙恩后的更新之歌放在“未认识神的迷茫”阶段：指出视角不符，而不是硬解释为迷茫。
- 缺第一阶段但后两阶段明确：保留用户选歌的可行性，说明用真实见证补背景或替换开场的取舍。
- 主题匹配但编曲更快：标出与慢速需求的冲突，不隐去 BPM。
- 仅凭标题发现“坚定跟随”候选但歌词空：标待核验，不作为已确认的更优选择。
- 无完整证据时允许给条件性建议，不编造歌词、试听结果或用户经历。
