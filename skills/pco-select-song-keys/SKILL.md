# 歌手配置、定调与试听

在 [完整 workflow](../../workflow/SKILL.md) 的第一段使用，命令接口见 [运行说明](../../workflow/README.md)。主题与选曲由现有选歌流程负责；本 skill 不擅自换歌或重新排序。

## 收集歌手信息

歌单明确确认后，再询问歌手低音、中音或高音，以及男、女歌手人数。同一性别有不同音区时按组记录，人数相加要与男女总数相等；只有一个人时仍明确音区，不默认为男中音或女高音。

用户知道时补充舒适最低/最高音、每首主领和领唱/和声分工。不知道音域不阻塞初步方案，但必须说明分类只是线索：低/中/高不是严格声部鉴定，男女数量也不等于哪组应该主领。

## 查询与推荐

- `key-requirements` 保存配置；`key-options` 查询已定编曲的现有 Key 和 MP3。必须查单个 Key 详情提供的附件链接，Key 列表省略链接不代表没有 MP3。
- 只选真实存在且可下载的 Key 专属 MP3。附件在具体 Key 下面就是关联依据；不按同歌名、原调、文件名猜调，也不把 PDF 上 `allow_mp3_download` 标志当成 PDF 是音频。
- 不创建 Key、不本地移调或转码。资源暂不可访问时报告未能验证，不擅自替换为别的调。
- 根据主领音区、可用舒适音域和旋律音域证据比较现有调；考虑持续高音、低音可听度、桥段、男女同唱可能的八度安排。没有实证时只给有条件建议，不能承诺“绝对舒适”。
- 不用统一的“男声唱 G、女声唱 C”等规则；调名本身不决定最高/最低音。八度安排属于演唱建议，不改变 MP3 Key，也不能声称 MP3 已作八度变换。
- `key-propose` 每首记录真实 Key ID、MP3 ID、建议主领组、选调理由、音域依据和未知项；保持已确认的三首歌序。默认一套优先定调，有必要才给其他实质不同的方案，不凑数量。

## 试听、反馈与确认

`key-preview` 只临时取得候选方案对应的三首原始 MP3，缓存和校验，不下载歌词，也不视为用户已经听过。使用真实本地文件供用户播放，明确目前是试听版本。建议歌手实际试唱关键高低句，不能将助手解码文件或自动播放完成当作用户试唱合适。

用户反馈偏高/偏低、主领改变或合唱不适时，记录 `key-feedback`，按已有调调整并重新试听。新方案不能沿用旧试听确认。

只有用户明确听完当前三首且表示没问题，才记录 `key-confirm`；歌单确认或实施代码的授权不能代替试听认可。程序保存试听文件哈希，正式交付必须与听过的字节一致。

## 统一交付

确认后由一次 `download` 处理中文歌词优先、简谱回退，以及对应 Key 的原始 MP3，尽量复用试听缓存。文档与音频独立报告，文档缺失仍可交付已批准的 MP3。不把其他调的谱冒充目标调；无调性证据的原始简谱可交付但标明未核验。禁止转录、OCR 或补写歌词。

修改歌手配置、定调方案会撤销定调确认并使旧话语稿失效，不撤销已定歌序；换歌、换序则必须重新定调。已有文件保留不覆盖，不允许旧调的谱或 MP3 静默成为新方案交付。
