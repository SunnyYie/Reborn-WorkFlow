# Mini 歌单 Workflow

先读 [CLI 与输入接口](README.md)。这是 Agent 对话编排加本地引擎，不是自动识谱或自动理解歌曲的模型。

## 路由和边界

- 用户给出三首与顺序即使用，不重新推荐，不要求主题、快慢、歌手配置或整份确认。
- 只使用 PCO 歌词字段或下载原件；不读 RAG、历史库或历史歌词，不调用完整 workflow 的定调/话语/组装命令，不创建虚假的 listened、选调或现场确认。
- 调、BPM 固定为空，即使 PCO/谱面有值或模板填过也不采用。另有定调需求转完整流程，不临时改 mini。
- 经文、祷告、话语未给就留空，不自动写；给定引文核验原文并忠实记录状态，无法核验可保留用户原文并在回复/sources 披露，不能标成已核验。
- 回应和结束未指定就保持空白，不追问。指定同曲复用本次材料，新曲也只查 PCO。
- 本 Skill 的 mini 规则优先于完整流程及组装 Skill 的 RAG 优先、必填项和确认门禁；模板字体、颜色、分页及安全边界继续适用。

## 执行

1. 新任务 `new`，保存实际 `state_path`；续接用 `status`，不另建会话。完整 workflow 的 state 不兼容。
2. `select` 可按精确标题解析唯一歌曲/编曲；标题、双语名、多版本有歧义时用 `catalog`、`inspect` 展示实际候选，让用户选择真实 ID。仅没有候选才记未找到，网络/权限失败不是没有。
3. `resources` 查看来源，`download` 下载：中文歌词优先，确无中文才取原始简谱；多份/跨编曲/分类不明用 `review-resources` 记录依据及真实版本选择，受限歌词不能降级绕过。
4. 逐首读取下载清单的实际原件。TXT/DOCX 整理为原文乐段；PDF/图片/简谱由 Agent 实际查看、逐处核对后通过 `material-prepare` 导入。下载本身不 OCR、不转录。没有识读能力或字不清时留空，issues 说明位置，不补词。
5. 结构有明确源顺序时采用；只有乐段清单时可提供 `proposal` 编排或将 route 留空。重复、编号按实际保留；LL/Tag 必须独立存在，不从副歌末句凭空抽取。小节、分工和强弱需逐条实际依据，不做音频分析。
6. `export` 直接生成 DOCX/sources，无整份人工确认步骤。缺失和失败均允许空槽位出稿，但回复逐项说明；不要把未导入歌词说成歌曲无歌词。歌词原件仍一并可交付，不生成虚构的歌词占位文件。
7. 在原生 WPS/Word 逐页检查本次实际文件，依 README 的 mini 验收规则 `artifact-finalize`。无法原生检查时保持待验收，不填模拟观察，不宣称交付完成。
8. 收尾只清理本会话登记且已被替代、哈希未变、实际观察已关闭的 DOCX/sources/预览；保留原件、state、材料依据及当前成品。用户改过、仍打开或不明归属的文件不删。

## 版式与反馈

直接使用保留模板及共享纯渲染器，不从空白文档重建，不用表格假冒歌词双栏。三首独立起页，回应/结束在新的独立页；新增回应展示完整歌词，结束只展示曲名和有依据的结构。口述附录仅用户提供时出现，另起页。

缺失内容保留标题、空经文栏和空结构表，不在正文加“待确认/资料缺失”等内部占位字样。编排建议及未核验状态写入回复和 sources，不把直接出稿误称为现场结构获批。

修改选择时重新提交完整 `select`（包含仍需保留的回应/结束/用户内容）；更换原件后重新导入受影响材料。相同请求与路径自动复用未变成品，其他情况不覆盖已有文件。

报告实际 state、三首顺序、文档/识读状态、缺失和异常、DOCX/sources、原生验收和清理结果。不下载/播放音频，不上传、不写回 PCO，不记录 Secret 或签名链接。
